个性化算法学习 LLM 教练系统 60 天详细执行计划

计划定位

这份计划默认你未来 60 天把主要精力投入到一个核心项目上：

个性化算法学习 LLM 教练系统

目标不是做一个普通 AI 壳子，而是做出一个：

  • 有真实问题定义
  • 有完整产品链路
  • 有 RAG / 用户画像 / 评测意识
  • 能在复试和面试中讲出技术深度

总目标

60 天结束时，你应该至少拿到这些结果：

项目结果

  • 一个可运行的前后端系统
  • 支持题目录入、思路录入、AI 结构化复盘
  • 支持历史记录查看
  • 支持基础检索增强
  • 支持初级用户画像

工程结果

  • GitHub 仓库持续提交
  • 前端与后端目录结构清晰
  • README 可读
  • 本地可启动
  • 最好有可演示版本

技术结果

你能讲清：

  • 为什么用 Python + FastAPI + Next.js
  • 为什么先做 structured output
  • 为什么后面加 RAG
  • 为什么要做画像和评测
  • 你做过哪些优化

每日投入建议

建议每日投入 5-7 小时。

标准版

  • 2 小时 学技术
  • 3-4 小时 开发项目
  • 0.5-1 小时 总结、提交 Git、记问题

每天固定动作

每天无论进度多慢，都要做这三件事：

  1. 写一点代码
  2. 提交一次 Git
  3. 记录今天卡在哪

技术栈主线

你这 60 天主要学什么

第一层：必须掌握

  • Python
  • FastAPI
  • Next.js
  • TypeScript
  • Git / GitHub
  • HTTP / JSON / API 调用

第二层：项目核心

  • Prompt 设计
  • Structured Output
  • OpenAI 兼容接口调用
  • 基本错误处理
  • 前后端联调

第三层：项目深度

  • Embedding
  • 向量检索
  • RAG
  • 用户画像
  • 推荐逻辑
  • 评测设计

第四层：后置理解

  • LoRA
  • SFT
  • 微调数据集格式
  • Prompt / RAG / 微调之间的边界

60 天分阶段

阶段 1：第 1-14 天

目标

先把最小可用系统立起来：

前端输入 -> 后端接口 -> 调用模型 -> 返回结构化复盘 -> 展示结果

这一阶段你重点学什么

  • Python 基础
  • FastAPI 最小接口
  • Next.js + TypeScript 最小页面
  • fetch 调接口
  • prompt 基础
  • Structured Output

阶段 2：第 15-30 天

目标

把 MVP 做完整：

  • 页面基本完整
  • 数据库存储
  • 历史记录
  • 基础筛选
  • 结构化 AI 结果保存

这一阶段你重点学什么

  • PostgreSQL
  • 数据表设计
  • CRUD
  • 前后端数据模型
  • 基本状态管理

阶段 3：第 31-45 天

目标

让项目真正开始有深度：

  • 加 RAG
  • 加历史复盘召回
  • 加知识点库
  • 加画像

这一阶段你重点学什么

  • Embedding
  • 向量库
  • Chunk
  • 检索策略
  • 用户画像聚合逻辑

阶段 4：第 46-60 天

目标

把项目从“能用”变成“能讲优化和实验”：

  • 做评测
  • 做失败样例分析
  • 对比 prompt / 检索策略
  • 整理 README / 演示材料
  • 初步理解微调

这一阶段你重点学什么

  • Evaluation
  • Prompt 对比
  • RAG failure cases
  • LoRA / SFT 入门概念

第 1-14 天详细计划

Day 1

目标

搭项目骨架

学习

  • 了解整个系统的前后端拆分
  • 搞清楚 frontend / backend 各做什么

实践

  • 创建项目总目录
  • 创建：
    • frontend
    • backend
  • 整理 GitHub 仓库
  • 写一个简短 README

当日产出

  • 项目目录结构存在
  • 仓库可提交

Day 2

目标

跑通 Python 后端最小服务

学习

  • Python 虚拟环境
  • pip
  • FastAPI 基础

实践

  • 在 backend 里创建虚拟环境
  • 安装：
    • fastapi
    • uvicorn
    • httpx
    • python-dotenv
  • 写：
    • GET /
    • GET /health

当日产出

  • 后端服务能启动
  • 浏览器访问 /health 能返回 JSON

Day 3

目标

跑通前端最小页面

学习

  • Next.js 创建项目
  • React 基础
  • TypeScript 基础类型

实践

  • 在 frontend 中创建 Next.js 项目
  • 选 TypeScript
  • 跑默认页面
  • 新建一个简单页面，展示标题和按钮

当日产出

  • 前端项目能运行
  • 页面可在浏览器打开

Day 4

目标

做输入表单

学习

  • React useState
  • 表单受控输入

实践

  • 前端页面加入输入框：
    • 题目标题
    • 难度
    • 标签
    • 思路
    • 卡住点
  • 做一个“生成复盘”按钮

当日产出

  • 页面能输入内容
  • 表单状态正常更新

Day 5

目标

打通前后端基础接口

学习

  • fetch
  • POST 请求
  • JSON 请求体 / 响应体

实践

  • 后端新增 POST /generate-review
  • 先返回固定假数据
  • 前端点击按钮后，把表单数据发给后端
  • 页面展示后端响应

当日产出

  • 前端输入 -> 后端返回 -> 页面展示 这条链路跑通

Day 6

目标

接入真实大模型接口

学习

  • OpenAI 兼容接口
  • 环境变量
  • Prompt 基础

实践

  • 配置 .env
  • 用 httpx 调用模型接口
  • 把假数据替换成真实生成内容

当日产出

  • 模型调用成功
  • 页面能展示真实 AI 输出

Day 7

目标

固定输出格式

学习

  • Structured Output 基础
  • 为什么不能让模型自由发挥太多

实践

  • Prompt 改成固定结构输出：
    • 错因分析
    • 核心知识点
    • 推荐思路
    • 下次注意点
  • 前端分模块展示结果

当日产出

  • 输出结果更稳定
  • UI 不再只是一大段文本

Day 8

目标

补错误处理

学习

  • FastAPI 异常处理
  • 前端 loading / error 状态

实践

  • 后端处理：
    • 接口超时
    • 空返回
    • 请求失败
  • 前端增加：
    • 加载中
    • 错误提示

当日产出

  • 项目不再一失败就白屏

Day 9

目标

整理前端页面结构

学习

  • React 组件拆分
  • 页面组织方式

实践

  • 把页面拆成组件：
    • 输入表单组件
    • 结果展示组件
    • 按钮与状态组件

当日产出

  • 前端不再堆成一个文件

Day 10

目标

设计数据库

学习

  • PostgreSQL 基础
  • 一对多关系
  • 什么是表设计

实践

  • 安装并跑通 PostgreSQL
  • 先画表设计：
    • problems
    • review_sessions
    • llm_outputs

当日产出

  • 数据库设计草稿完成

Day 11

目标

把数据库接到后端

学习

  • Python 连 PostgreSQL
  • 基础 CRUD

实践

  • 后端连上数据库
  • 支持创建一条 review 记录

当日产出

  • 不只是生成结果，还能保存结果

Day 12

目标

做历史记录页面

学习

  • 列表渲染
  • 从后端读取数据

实践

  • 新建历史记录页
  • 调后端接口拿 review 列表
  • 页面展示标题、时间、难度、标签

当日产出

  • 历史页能看见多条记录

Day 13

目标

做详情页

学习

  • 动态路由
  • 详情页数据获取

实践

  • 点击某条历史记录进入详情页
  • 展示：
    • 原题信息
    • 用户输入
    • AI 输出

当日产出

  • 项目第一次有完整闭环

Day 14

目标

完成第一个可演示版本

学习

  • README 最小写法
  • 项目自测思路

实践

  • 修明显 bug
  • 更新 README
  • 补截图
  • 做一次完整演示流程

当日产出

  • 第一阶段可用版

第 15-30 天详细计划

这一阶段不再按每天极细拆，而按 2-3 天一个主题推进。

Day 15-17：完善数据模型

学什么

  • 更清晰的表结构设计
  • 用户、题目、复盘记录之间的关系

做什么

  • 扩展数据表
  • 增加更多字段：
    • 错误代码
    • 难度
    • 标签
    • 用户状态

产出

  • 数据层更像正式系统

Day 18-20：补完整的 CRUD

学什么

  • 更新接口
  • 删除接口
  • REST 风格基本概念

做什么

  • 支持编辑历史记录
  • 支持删除记录
  • 支持重新生成 AI 复盘

产出

  • MVP 像一个真正产品

Day 21-23：筛选与搜索

学什么

  • 多条件筛选
  • 前端状态与查询参数

做什么

  • 按难度筛选
  • 按标签筛选
  • 按关键词搜索

产出

  • 历史记录页面明显更实用

Day 24-26：基础统计页

学什么

  • 统计聚合思路
  • 前端图表可后置，先做文本统计

做什么

  • 总题数
  • 总复盘数
  • 常见标签
  • 最近错误模式

产出

  • Dashboard 初步成型

Day 27-30：前后端整理与第一次上线准备

学什么

  • 项目目录整理
  • .env 管理
  • 本地启动说明

做什么

  • 清理文件
  • 补 .env.example
  • 补启动文档
  • 做一次本地完整验收

产出

  • 第二阶段完成，MVP 完整版可展示

第 31-45 天详细计划

Day 31-33：知识点库准备

学什么

  • 什么内容适合做检索知识库

做什么

  • 准备知识点材料：
    • 数据结构常见知识点
    • 算法题型总结
    • 常见错误模式

产出

  • 初版知识点库文本

Day 34-36：Embedding 入门

学什么

  • embedding 是什么
  • 为什么 RAG 不是简单关键词搜索

做什么

  • 给知识点库和历史复盘做向量化

产出

  • 你第一次具备向量检索材料

Day 37-39：接入向量检索

学什么

  • 向量库基础用法
  • 相似度检索

做什么

  • 查询相似历史复盘
  • 查询相关知识点块

产出

  • 项目开始有基础 RAG

Day 40-42：把检索结果喂给模型

学什么

  • RAG 上下文拼接
  • 检索结果如何影响生成

做什么

  • 在生成前拼接：
    • 当前题目信息
    • 历史相似复盘
    • 相关知识点

产出

  • 输出开始更贴近你的真实场景

Day 43-45：初版用户画像

学什么

  • 画像是聚合，不是魔法

做什么

  • 汇总：
    • 常错标签
    • 常见错误模式
    • 薄弱知识点
  • 前端做一个简单画像页

产出

  • 项目明显开始有“个性化”味道

第 46-60 天详细计划

Day 46-48：设计评测集

学什么

  • 什么叫评测样本
  • 为什么不能只凭感觉判断 AI 好不好

做什么

  • 整理一批真实样例
  • 给每条样例定义“期望输出方向”

产出

  • 小型评测集

Day 49-51：设计评测指标

学什么

  • 完整率
  • 相关性
  • 命中率

做什么

  • 至少记录：
    • 输出字段完整率
    • 检索命中率
    • 用户主观帮助度

产出

  • 项目第一次能“量化评估”

Day 52-54：做 prompt 对比

学什么

  • Prompt 版本对比思路

做什么

  • 准备 2-3 个 prompt 模板
  • 对比输出质量

产出

  • 一组可讲的实验结果

Day 55-56：做 RAG 对比

学什么

  • 有检索 vs 无检索 的差别

做什么

  • 比较：
    • 纯 prompt
    • 加历史复盘
    • 加知识点库

产出

  • 你能明确讲清 RAG 的价值

Day 57-58：失败案例整理

学什么

  • 为什么失败案例比成功案例更重要

做什么

  • 记录常见失败：
    • 输出空话
    • 推荐偏题
    • 检索误召回

产出

  • 失败样例库

Day 59：README 与演示视频

学什么

  • 怎么描述项目
  • 怎么组织 Demo

做什么

  • 写 README
  • 补项目截图
  • 录 1-3 分钟演示

产出

  • 可以公开展示的版本

Day 60：讲稿与下一阶段规划

学什么

  • 怎么把项目讲得像“自己真的做过”

做什么

  • 准备：
    • 3 分钟讲稿
    • 5 分钟讲稿
    • 10 分钟讲稿
  • 总结下一阶段：
    • rerank
    • 更完整的画像
    • 微调入门

产出

  • 60 天阶段性完成

60 天后如果继续加时间

再加 30 天，优先做什么

  • 更强的评测面板
  • rerank
  • 更精细的画像
  • 初步 LoRA / SFT 实验

再加 60 天，优先做什么

  • 做成真正代表作
  • 打磨系统架构表达
  • 完善实验设计
  • 形成复试/面试主项目

你每天都要提醒自己的事

1. 先做出来，再做深

不要还没跑通最小闭环，就去想微调和 Agent。

2. 项目深度不等于功能数量

真正的深度来自：

  • 结构化输出
  • RAG
  • 画像
  • 评测
  • 优化过程

3. 每周都要有能看见的产出

不要出现“学了很多，但项目没变化”。

最后一句

这 60 天里，你的主线不再是“学各种技术”，而是：

围绕一个项目，按问题驱动去学技术。

只要你连续推进 60 天，这个项目就会明显强于普通课程项目。
如果再多打磨 30-60 天，它就很有机会成为你复试和面试中的核心优势。
